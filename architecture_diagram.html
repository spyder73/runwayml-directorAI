⚡ LLM Request Points (OpenRouter)

The system makes several OpenRouter calls, highlighted in glowing gold on the diagram:

  • Director AI (Interview): Runs on the composed interview system prompt and decides whether to chat or call tools.
  • Director Continuation (Fallback): When tool output needs wrapping into natural user-facing follow-up, a continuation prompt is sent.
  • Shot Planner (Production): Generates structured shot plans for scene duration and camera changes.
  • Shot Plan JSON Repair (Fallback): If planner output is malformed, a repair call converts text into strict JSON shots.
  • Prompt Moderation: ensureSafePrompt evaluates and optionally rewrites image/video prompts.
  • Video Prompt Repair: Repairs motion prompts that fail lint/validation (with deterministic fallback if needed).

1. Interview Prompt Injection

Before each interview turn, buildInterviewSystemPrompt composes one system prompt from reusable prompt modules plus private DB context.

  • sharedDirectorPrompt (global Director behavior).
  • phasePrompt(...) for onboarding/profile/deep-interview stage.
  • referenceUploadPrompt, sketchFeedbackPrompt, and scene-outline prompts (including diversity/revision rules).
  • Private context injection: story bucket facts, upload vision notes, and active reference-upload request state.

2. AI Tools Access

The Director LLM extracts data from the conversation by calling structured JSON tools:

  • update_profile_bucket: Upserts personal facts and themes into the DB.
  • request_reference_upload: Prompts the UI to ask the user for a specific photo.
  • propose_scene_outline: Writes the actual script, splitting the story into discrete SceneRow database entries.

3. Knowledge Storage

Knowledge is stored in SQLite and heavily divided:

  • StoryBucket: The narrative truths (who, what, where, themes).
  • Reference Assets: Links user-uploaded images to specific Entities (e.g., Image #123 belongs to the entity "My Mom").

4. Production Prompt Lifecycle

After outline approval, prompt flow is explicit and layered: shot planning, moderation, validation, and repair.

  • Shot planning: planShots requests structured shot JSON. If schema output is malformed, a repair LLM pass rewrites it to strict JSON.
  • Prompt moderation: ensureSafePrompt is called for scene image prompts, continuity-frame prompts, and shot video prompts.
  • Repairing now visible: video prompts run through lint; failing prompts enter repairRunwayVideoPromptForValidation, then are re-linted before Runway.
  • Continuity step: for multi-shot scenes, continuity reference-frame prompts are generated so later shots stay visually consistent.
